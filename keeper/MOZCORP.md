# MozCorp private rooms · 0.15b

## Install your rooms

Open **MozCorp** in Keeper and choose the matching private ZIP with **Choose private bundle**. Keeper checks its complete size, fingerprint and file inventory before activating it. A failed upload leaves the installed bundle intact. Use the ZIP prepared for this Keeper version; an unrelated or modified bundle is refused.

The public app contains a generic loader and the approved bundle fingerprint. Private station source stays in the separately installed bundle in Keeper's data. Rooms run in isolated, opaque-origin frames with no direct access to the parent app's storage or network. Home Assistant keeps its normal authenticated ingress. This isolation is not an independent security certification.

Version 0.15b requires its matching private bundle to fix paragraph breaks in newly generated stories. Update this same Keeper app, then replace the private ZIP when prompted. Existing saved endings remain exact. The loader continues checking the complete bundle before activation.

## Create, save and score a world

The authentic MozCorp machine and the separate playable Bug World use Keeper's creative project shelf. **Save world**, **Open**, **Export project** and **Import project** carry their supported state between sessions. Other desks retain their own local exports.

Projects are **unencrypted browser data**, separate from the encrypted vault. Keep portable exports of work you want to retain. The shelf is shared only within the same browser profile and origin; another browser, address or port needs explicit export/import.

**Edit soundtrack** opens the same project in Dot Studio. Save the edited score back to the project to carry it with the world. Original input, protected master, source mode and literal generated outputs remain separate fields. Reopening a project does not run the machine, turn held personal text into fiction or feed FINAL STORY // EXIT back into the hopper. The original cloud snapshot still excludes that final story; its literal text is kept separately in the project.

A legacy `.btwpkg` uses the actual Bug World importer, rather than being treated as a current-machine cloud save. The complete legacy payload is retained as inert JSON, including its original fields and source material. Embedded script text is never executed. Restored Bug World progress starts paused; press **Resume** when ready. Imports open a candidate room before replacing the active room, so a failed restore preserves the current work.

## Credits and Blooper Reel

The private machine keeps **13 · Voo Don't**, adds **14 · Credits** and **15 · Blooper Reel**, and retains its unnumbered hardwired **Story / Exit** at the end of the patch bay. The two added modules have independent switches and intensity controls.

Credits list the fictional cast and active machine crew. Blooper Reel uses only actual pre-story excerpts from Poem Gen, Telephone and Hivemind; intensity changes their count and length. It does not invent quotations or alternate endings. Empty, bypassed and duplicate takes are excluded. Personal, observer and talky source modes skip both cards.

The cards persist as literal outputs, separate from the source, protected master and final story. They never enter story feedback or change the Studio soundtrack.

## Shared savepoints and HOPE-LON

Shared savepoints live in this Keeper's server storage and are available to people authorized to open its Home Assistant app. They follow the original pre-story snapshot boundary: the final story is excluded. Use **Save world** and a portable project export for the complete narrative, protected master and attached Studio score.

The service holds up to 24 savepoints, each at most 120,000 UTF-8 bytes. At capacity it refuses another save instead of removing an old one. Export a backup before deleting records. Restoring opens a candidate room first; a failed restore preserves the active room.

Existing records on the original private site do not appear automatically. Export them there and explicitly import the matching savepoint data into this Keeper. Exporting or importing a savepoint is separate from an encrypted vault backup.

HOPE-LON keeps its fictional feed and solved-case records in the same Keeper service storage. It starts paused. It does not copy accounts or records from the original site and does not add social posts, likes or membership services.

## Telephone Dating in Home Assistant

Open **Telephone Dating** from Keeper's sidebar while using the authenticated Home Assistant Web UI over HTTPS. The page stays inside that app frame and offers **Back to Keeper**; the story tools and installed MozCorp rooms remain available through their usual navigation.

Sign in with your **existing dating key** to use the same dating profile, matches and conversations as on the public dating site. That key starts with `btw_` and is separate from your Home Assistant password. No key is copied from another app. Creating another account is a secondary, explicit choice for people who do not already have a dating account.

The page checks that its shared service is ready before sign-in or registration. Outside HTTPS, or while that check fails, it sends no dating key. **Public dating site** opens the separate site only when selected and carries no key in its link. This page does not read contacts, world saves, private desk notes or the Keeper vault, and it creates no separate local profile store.

## Keep desk boundaries intact

EVERYWHEN transfers only its approved fictional scene and creative icon cue. Sensations, notes, weather, receipts, full receipt hashes and synthetic RAM buffers stay outside that transfer. The cue travels through a one-use in-memory handoff; using its preview in the hopper remains an explicit action.

Integrity receives a separate one-use source-review handoff. An occupied notebook asks before replacement; cancellation keeps its notes and pending transfer. Integrity notebooks and CSV analysis are not captured in world projects. Use that desk's own exports for copies you want to keep. Other private desks likewise retain their own export controls.

Only the native Mozmoji dictionary and Voo Don't preferences persist through Keeper's preference bridge: `btw.mozmoji.fork.v1` and `btw.voodont.blind-backfeed.v1`, stored under `doodleverse-mozcorp-preferences-v1`. This does not grant a private frame access to other browser storage.

## News and the original site

**News Grabber** fetches headlines only after an explicit action. Keeper makes a bounded request to a fixed Google News RSS endpoint, then returns headline text and source links. A headline is source material, not verified evidence. Remote executable news scripts are not loaded into the rooms.

Use **Open original private site** to open its separately hosted copy. Keeper's local service records are separate; they do not silently update that site's records or reuse its authentication.

## Upgrade proposals in Keeper

Open the upgrade proposal desk to choose an area, identify the base release and write an instruction. **Manual proposal** works without an AI provider key. Enter a title, summary, individual changes and reasons, privacy impact, review checks, rollback plan and risk level, then save the proposal for review.

When AI is configured, save **Allow external AI proposal requests** before choosing **AI proposal**. Each request also needs a fresh instruction-only consent. Only the selected area, the instruction you enter and the base release reference are sent to the provider. Manual proposal fields, world saves, private desk notes, files and vault contents are excluded. Missing configuration is shown explicitly; the manual workflow remains available.

For Home Assistant, set `mozcorp_ai_enabled`, `mozcorp_openai_model` and the password field `mozcorp_openai_api_key` in the app configuration, then restart the app. Desktop Keeper reads `OPENAI_API_KEY` and `OPENAI_MODEL` when it starts. Keys remain on the server; do not put them in an instruction. Configuration alone makes no AI request: the saved preference and consent for an individual request are still required.

If Home Assistant hides the key field, turn on **Show unused optional configuration options**. The translated **OpenAI API key** field for proposals is above the separate Jazz options. Enter and save the key directly there, then restart Keeper. The proposal desk reports whether a key is configured without revealing it.

Recognized provider failures show fixed notices for authentication, project permissions, quota, temporary rate limits, unavailable models, rejected requests or service failures. Check the indicated account or setting before choosing another request. Unknown failures remain generic; no provider error text is displayed, and there is no automatic retry. A configured key still needs valid provider access and available usage limits.

Saved proposals retain their instruction and structured details for every version. Review the current version, then approve or decline it. **Revise proposal** creates another version and returns it to review; an earlier approval does not approve the new version. Stale writes are refused, so refresh after another user changes the desk. Your unsaved form stays available when a request fails.

After a separately completed release, use **Record completed deployment** with its release reference. A recorded deployment can later receive a completed rollback reference. These actions save review records; the desk does not install or restore code. Deleting a proposal removes its saved instructions and versions after confirmation, while metadata-only audit events remain.

**Export proposals** downloads a versioned JSON copy of the instructions, proposal versions and audit records. Provider credentials are excluded. The export is unencrypted and intended for review and backup; this desk has no proposal-import action.

Proposal instructions, versions and audit records persist in this Keeper's service storage, shared by its authorized app users. They are separate from the encrypted creator vault and portable world projects. Use the existing Keeper backup procedure for the server's service records.

## Contributor boundaries

Keep private station source out of the public repository and release assets. Update the approved fingerprint only after rebuilding and checking the matching private bundle. Preserve the narrow message contract, opaque frame policy, source-handling protections and distinction between project state and private desk exports.

Local source checks, disposable engine tests and simulated ingress checks establish only their tested behavior. They do not by themselves verify a physical Home Assistant installation, long playback or operation across separate devices.
